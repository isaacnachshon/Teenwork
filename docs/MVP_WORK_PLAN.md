## תמונת מצב מאומתת לפי פרסונה (10 בספטמבר 2026)

### עדכון יישום ניהול משרות

### פרטי מועמדים ודירוגים הדדיים

נוספו פונקציות שרת `getRelatedProfile`, `submitRating`, `getRankings`.
פרופיל מקצועי מסונן נגיש לצד השני רק לאחר אימות קשר דרך מועמדות. רשימות
מועמדים מסוננות גם לפי מזהה המעסיק. ב״התקשרויות״ נוספו פרטים ודירוג לאחר
השלמת העסקה; לשונית דירוגים מציגה עובדים ומעסיקים עם ממוצע ומספר דירוגים.
כל צד יכול לעדכן דירוג אחד לכל העסקה. הכללים המקומיים חוסמים שינוי תפקיד עצמי,
מאמתים בעלות משרה בעת הגשה ומגבילים שדות בעדכון מועמדות.
בניות frontend ו־Functions עברו; בדיקות יחידה של לוגיקת השרת עברו עם מסד מדומה.
נדרשת פריסה של Functions והכללים כדי להפעיל את השינוי באתר. טרם נבדק מול
אמולטור Firestore או האתר החי; אין לראות בבדיקות המדומות אימות של rules.

**עדכון אחרון:** גם מסלול העובד מחובר כעת ללשונית "חיפוש משרות" דרך
`JobSearchPage`: הרשימה והסינון הקיימים, פרטי משרה, הגשת מועמדות וחזרה לרשימה.
שתי בדיקות ב־`tests/dashboard/flows.spec.ts` עברו דרך `DashboardLayout` האמיתי:
עסק יוצר ועורך משרה, מתאושש מכשל כתיבה וצופה בפרטי מועמד; עובד פותח משרה,
מגיש מועמדות ורואה אישור. נתוני Firebase מוחלפים רק בחבילת הבדיקות המבודדת,
ומסכי הסקירה והאזורים הלא נבדקים מוחלפים בסטאבים. אין בכך אימות של הרשאות
שרת או של הפריסה החיה. להרצה: `npx playwright test --config playwright.dashboard.config.ts`.

**המשך נדרש:** אימות מול Firebase emulator או חשבונות בדיקה מאושרים. בפרט,
כללי `users` הנוכחיים מתירים קריאה רק לבעל הרשומה או לאדמין, ולכן פרטי מועמד
עלולים להיות חסומים למעסיק. יש לתכנן גישה מצומצמת לפרטי מועמד לפני הרחבת
הרשאות. כללי האבטחה לא שונו במסגרת חיבור המסכים. ניהול משמרות ושעות אינו
כלול בשינוי זה. תיאורי החסר של חיבור מסכי העסק והנוער בהמשך המסמך היסטוריים;
החיבור הושלם, ואימות backend עדיין פתוח.

נוספה לשונית "ניהול משרות" בתפריט העסק ב־`DashboardLayout`, המחברת את
`EmployerDashboard` במצב משולב ללא תפריט צד נוסף. פרסום, עריכה, מחיקה וצפייה
במועמדים נגישים כעת מהלשונית. נוספו מצב טעינה ושגיאת טעינה, ולידציה לפני
שמירה, מניעת שליחה חוזרת ושמירת פרטי הטופס כשכתיבה נכשלת. נתוני דוגמה של
מועמדים ותשלומים הוסרו ממסך זה. הבנייה המקומית עברה. טרם אומת מסע CRUD
מחובר מול Firebase; תיאור החסר של חיבור ניהול המשרות בטבלה למטה הוא מעתה
היסטורי. השלב הבא לעסק הוא אימות פרסום→עריכה→מחיקה בסביבת בדיקה עם חשבון מעסיק.

> מקור האמת בבדיקה זו הוא הנתיב הפעיל `App.tsx` → `DashboardLayout.tsx`, ולא
> הדשבורדים הישנים `TeenDashboard.tsx`, `EmployerDashboard.tsx` ו-`AdminDashboard.tsx`
> שעדיין קיימים בקוד אך אינם נטענים בזרימה הראשית. `npm run build` עבר, ו-44/44
> בדיקות Playwright עברו; עם זאת, הבדיקות הנוכחיות בודקות בעיקר דפי נחיתה,

### סטטוס רוחבי וקריטריון ההתקדמות הבא

- **תקין כעת:** build ל-production עובר (84 מודולים). כל 44 בדיקות ה-UI הקיימות עוברות.
- **חוב טכני גלוי:** bundle ראשי בגודל כ-1.18MB לפני gzip ומתקבלת אזהרת chunk גדול; קיימים שני סטים של דשבורדים, והסט העשיר הישן אינו מחובר לנתיב הפעיל.
- **חסם MVP אמיתי:** אין עדיין הוכחה אוטומטית לאף אחד משלושת המסעות לאחר התחברות, וחלק מפעולות הליבה של מעסיק ונוער אינן נגישות דרך האפליקציה הפעילה.
- **השלב הבא המומלץ:** לאחד קודם את הדשבורדים בתוך `DashboardLayout` (מעסיק: ניהול משרות; נוער: חיפוש והגשה; אדמין: מודרציה), ורק לאחר מכן לבנות שלושה תרחישי E2E מחוברים מול Firebase emulator. אין לסמן MVP מוכן על סמך 44 הבדיקות הנוכחיות בלבד.

## 1. הגדרת ה-MVP — מה חייב לעבוד כדי להשיק

ה-MVP מוגדר לפי **שלושה מסעות משתמש שחייבים לעבוד מקצה-לקצה עם נתונים אמיתיים ב-Firestore**:

| # | מסע | חייב לכלול |
|---|------|-----------|
| A | **נוער (14–18)** | הרשמה → אימות אימייל → בניית פרופיל → חיפוש/סינון משרות → הגשת מועמדות → מעקב אחרי סטטוס |
| B | **מעסיק** | הרשמה → פרסום משרה → צפייה במועמדים → קבלה/דחייה/יצירת קשר |
| C | **מנהל** | כניסה מאובטחת → דשבורד → ניהול/מודרציה של משתמשים ומשרות |

**קריטריון השקה (Definition of Done ל-MVP):** כל שלושת המסעות עוברים בדיקת E2E ירוקה, ללא נתוני mock, עם כללי אבטחה ב-Firestore, ללא סודות ב-frontend, פרוס על production, ועם עמודי חובה משפטיים (פרטיות קטינים + זכויות נוער).

### מחוץ לגבולות ה-MVP (נדחה ל-Post-MVP)
- Phase 4 (refactoring עמוק), Phase 5 (אופטימיזציית ביצועים / React Query / code-splitting), רוב Phase 6 (TS strict מלא, Husky).
- שפות מעבר לעברית (אנגלית/ערבית כבר קיימות מ-Phase 8 — נשארות, לא נבדקות לעומק ל-MVP).
- צ'אט בזמן אמת, נוטיפיקציות push, המלצות חכמות.
